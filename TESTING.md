# Проверка SSTP Client GUI 1.5.0 на реальном сервере

Изменения [PR #2](https://github.com/tolabzik/sstp_client_gui_mac_os/pull/2) включены в `main` и версию 1.5.0 (build 12).
Локальные проверки и CI проходят. На macOS 26.6.2 arm64 прошли два последовательных
цикла подключения и отключения: трафик через PPP, приоритет `host:port`, очистка DNS
и восстановление маршрутов подтверждены.

Рабочий профиль не проверял сертификат; сложный пароль и сервер на нестандартном порту
в этих сеансах не проверялись. Эти случаи, watchdog и первый неповторившийся сбой
Full Tunnel отслеживаются в [issue #3](https://github.com/tolabzik/sstp_client_gui_mac_os/issues/3).
Автотесты паролей и TLS не заменяют соответствующие проверки на реальном сервере.

## Подготовка

1. Используйте тестовую VPN-учётную запись. Не публикуйте пароль или приватный ключ сервера.
2. Установите исправленный компонент через **Setup → Install components / Upgrade SSTP component**
   или из основной ветки публичного tap:

   ```bash
   brew tap tolabzik/sstp-client-gui https://github.com/tolabzik/sstp_client_gui_mac_os.git
   brew install tolabzik/sstp-client-gui/sstp-client-gui
   ```

3. Проверьте `$(brew --prefix)/opt/sstp-client-gui/sbin/sstpc --version`:
   в выводе должен быть отдельный маркер `sstp-gui-fixes-1`.
4. Запустите приложение 1.5.0 из распакованного релизного ZIP или `dist/SSTP Client GUI.app`
   после локальной сборки. Не заменяйте рабочую версию приложения для первого теста.
5. В Setup нажмите **Check again**. Компонент должен определиться как исправленный.
6. Создайте отдельный профиль `Issue 1 test`, чтобы не перезаписать рабочий профиль.
   Сначала выключите Full Tunnel и отключите другие VPN, способные изменить маршруты.

## Проверки

| Проверка | Ожидаемый результат |
| --- | --- |
| Server без порта, Port = фактический нестандартный порт | Соединение устанавливается; Network Health и VPN SERVER TCP используют этот порт |
| Server = `host:port`, отдельное поле Port отличается | Порт из Server имеет приоритет; в маршруте остаётся только host |
| Перезапуск приложения и выбор сохранённого профиля | Адрес и порт восстановлены |
| Старый профиль без поля порта | Загружается; применяется 443 |
| Пароль тестовой учётной записи содержит `"` и `\` | Проходит настоящая авторизация; доступен трафик через PPP |
| Корректный публичный сертификат, пользовательский CA не выбран | Соединение проходит с проверкой цепочки и имени |
| Корректный сертификат частного CA, выбран его файл | Соединение проходит |
| Сертификат доверенного CA для другого имени | Соединение отклоняется до передачи PPP-учётных данных |
| Недоверенный или просроченный сертификат | Соединение отклоняется при включённой проверке |
| Явно выбранный CA-файл удалён | Понятная ошибка; автоматического обхода проверки нет |
| Disconnect | PPP и маршруты этого подключения очищены; обычный Internet работает |
| Full Tunnel включён после успешного первого теста | Трафик идёт через PPP, а маршрут до самого сервера — через физический интерфейс |
| Сервер разрывает соединение при Full Tunnel | Watchdog восстанавливает сеть и пишет сообщение об отключении |

Приложение проверяет доступность Internet через PPP даже с выключенным Full Tunnel.
Тестовый сервер должен разрешать этот трафик, иначе существующая проверка подключения
завершится ошибкой. Нельзя считать такой результат доказательством ошибки пароля.

Для отрицательных TLS-проверок нужны серверные тестовые сертификаты с соответствующими
свойствами. Отключение проверки сертификата не является успешным прохождением этих тестов.

## Что записать

- macOS, архитектуру, полный вывод версии исправленного `sstpc`;
- фактический порт и какие строки таблицы проверены;
- результат авторизации, передачи трафика и восстановления сети;
- при ошибке — диагностический отчёт после проверки на чувствительные данные.

Отчёт может содержать внутренние адреса, DNS и сетевые маршруты. Пароль и приватные
ключи не прикладывайте. При сбое сначала используйте Disconnect / Repair this app.
Emergency repair может завершить другие SSTP-сессии, поэтому используйте его только
если обычное восстановление не помогло и другие SSTP-подключения не нужны.

## Возврат к рабочему компоненту

Закройте тестовую сборку после отключения VPN. Отдельный keg можно удалить:

```bash
brew uninstall tolabzik/sstp-client-gui/sstp-client-gui
```

Обычный `sstp-client` этим не удаляется. Запустите прежнее приложение.
